# 導師共享登入工作台

多個導師檔案可以使用同一個已確認的 Supabase Auth 電郵。每個檔案仍有獨立 ID，可分別編班；登入後按同一 Auth 使用者 ID 讀取合併工作台。相同電話只作提示，不會用作身分連結。

## 啟用順序

1. 在目標 Supabase 專案 SQL Editor 執行 `supabase/tutor_portal.sql`，建立導師工作台、請假申請、點名表及 RLS。原有 `swim_app_data.students` 不會更改。
2. 部署 `supabase/functions/swim-admin-gateway/index.ts` 到同名 Edge Function。此函數須保持 `verify_jwt = false`，由函數內核對 Supabase Auth token、管理員白名單或導師工作台綁定。
3. 部署 `dist/` 到網站。管理員登入後，先在「個人資訊」建立導師檔案、課程和編班。共享電郵會即時要求確認。
4. 在「帳戶管理」按「同步導師資料」。管理員每次更改導師或課堂後須重新同步；同步失敗時本機資料仍保留，導師看到上次成功同步的版本。
5. 在 Supabase Authentication → Users 邀請導師使用已輸入的電郵。由導師本人在郵件連結設定密碼。該電郵必須已確認；不能在導師表單中設定或儲存密碼。若邀請早於同步完成，待同步後重新整理導師工作台。

導師工作台上載導師身分名稱、可負責課程、獲編配課堂日期時間與地點、該班學生的 ID 和姓名、月度班數和去重工時。不包含學生聯絡資料、付款、剩餘堂數或完整本機備份。導師只可讀自己的工作台、點名紀錄及請假申請；管理員保留總覽和處理權。

導師在課堂當日或之後，只可標記「出席／缺席」。缺席不即時扣堂。管理員在「帳戶管理」的「導師點名待處理」填寫缺席原因，選擇指定日期補堂、下星期補堂或不補堂，然後按「套用到學生紀錄」。出席及缺席不補堂各扣一堂；缺席補堂先改期，完成補堂時才扣堂。每筆套用在本機學生歷史以雲端點名 ID 記錄，網絡中斷重試不會重複扣堂。導師和管理員須使用同一份已核對的編班資料；若本機找不到對應學生或課堂，管理員要先核對，不能自動套用。

同時段的多班會逐班計入「班數」，但工時按日期合併重疊時段，只計一次。共享帳戶薪金暫不計算，待確認時薪及同時段計薪規則。舊課堂紀錄若沒有 booking ID，會按日期、時間、課程、地點及導師作近似去重；需要核對重要月結。

現有主網站仍會把學生和付款資料存放在管理員瀏覽器的 `localStorage`。不可在共用瀏覽器將導師登入視作已隔離本機資料；需要完整跨裝置保護時，須另行遷移主資料並清理舊瀏覽器儲存。
