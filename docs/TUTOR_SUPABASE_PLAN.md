# 導師帳戶與權限接駁草案

目前 `dist/` 只保存導師名冊、時薪、可負責課程、可授課時段及**權限意向**於瀏覽器本機儲存。電郵只是聯絡／日後登入識別欄位；密碼欄位停用，完全不讀取或儲存。現時所有使用同一瀏覽器的人仍可看到本機資料，並無真正的身份驗證或權限控制。

正式啟用前，須另行取得使用者對雲端同步及資料遷移的明確確認，然後：

1. 以 Supabase Auth 建立導師帳戶及邀請／重設密碼流程。密碼只由 Supabase Auth 管理，不回存到此應用、Git 或備份。前端只可使用 Supabase 公開 anon key；service role key 必須留在受保護的伺服器環境。
2. 建立 `profiles` 表，以 Auth user ID 關聯導師資料。時薪應由負責人限定閱讀，不要連同公開導師名冊一起暴露。
3. 建立導師與課程、學員與課堂的關聯表。以資料庫 Row Level Security (RLS) 和安全的伺服器操作實施權限，不能只靠隱藏按鈕。
4. 導師預設只能閱讀獲指派學員及課堂；若負責人開啟對應權限，可修改獲指派課堂紀錄與自己的教學筆記。不能閱讀全體學員、其他導師時薪、付款與管理設定；不能自行提升權限。
5. 負責人可管理所有課程、學員、導師及權限。家長帳戶之後需獨立角色，只可閱讀自己子女資料，不與導師角色混用。
6. 先在測試環境驗證登入、RLS、邀請、撤銷權限與資料備份，再規劃本機資料搬遷、衝突處理及正式上線。

本文件只是待實施規格；目前沒有接駁 Supabase、建立用戶、雲端同步或自動對外發送。
